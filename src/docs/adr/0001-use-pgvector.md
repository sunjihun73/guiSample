# 0001. pgvector를 벡터 저장소로 사용

- 상태(Status): 승인됨(Accepted)
- 날짜(Date): 2026-06-05

## 배경(Context)

RAG 기능을 구현하기 위해 임베딩 벡터를 저장하고 유사도 검색을 수행할 벡터 저장소가 필요하다. 본 프로젝트는 학습 및 검증을 목적으로 하는 토이 프로젝트(toy project)이며, 기존 스택은 PostgreSQL을 데이터베이스로 사용하고 있다.

## 결정(Decision)

toy project로 RAG를 구현해보기 위해 pgvector를 선택함.

기존에 사용 중인 PostgreSQL에 `pgvector` 확장을 추가하여 벡터 저장 및 유사도 검색을 처리한다. 별도의 전용 벡터 데이터베이스를 도입하지 않는다.

## 근거(Rationale)

- 이미 사용 중인 PostgreSQL을 그대로 활용할 수 있어 인프라가 단순하다.
- 별도의 벡터 DB(예: Pinecone, Weaviate, Milvus 등)를 추가 운영할 필요가 없다.
- 토이 프로젝트 규모에서는 pgvector의 성능과 기능으로 충분하다.
- 관계형 데이터와 벡터 데이터를 동일 트랜잭션/쿼리 내에서 함께 다룰 수 있다.

## 결과(Consequences)

- 장점: 운영 복잡도 감소, 학습 비용 절감, 단일 데이터베이스로 일관성 유지.
- 단점: 대규모 트래픽이나 초대용량 벡터 데이터 환경에서는 전용 벡터 DB 대비 확장성에 한계가 있을 수 있다.
- 향후 규모가 커질 경우 전용 벡터 저장소로의 마이그레이션을 재검토할 수 있다.
